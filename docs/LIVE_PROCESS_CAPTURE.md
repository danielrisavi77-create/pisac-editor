# F5-C: local capture of real document transactions

## Agreed scope

Owner explicitly requested detailed document-operation history, timestamped process and hashing, followed by a local implementation before any backend. This is a narrow F5 extension of the earlier F1 no-keystroke-logging rule: F1's payload-free dirty signal and durable document journal remain unchanged. No physical key events, global clipboard reads, other applications, browser history or covert tracking are introduced. Capture is OFF until the user deliberately starts a session on `/demo`.

## Actual integration

`Editor.tsx` exposes an optional stable ready callback. The demo wrapper subscribes to Tiptap's committed `transaction` event only while enabled, captures both the root and appended document-changing transactions, and stops the subscription synchronously when the user ends the session. Selection/focus-only events are ignored. The wrapper is dynamically imported; the existing initial bundle ceiling is not increased.

The capture records ProseMirror step JSON, NOT an invented sequence of inferred letters. The existing document at start is a baseline snapshot. `Step.fromJSON` with the actual editor schema replays insertions, replacements, deletions, formatting and structure changes including the steps generated by undo/redo. History operation labels are not inferred from private plugin metadata. Composition/paste/drop metadata, when provided by the editor, is labelled as observed. `editor` means unknown origin: typing, dictation, autocorrect or a programmatic command may all appear here. It never means verified human authorship.

Every record has a synchronous sequence number and observed wall-clock/monotonic elapsed time, a previous event hash, the step JSON and hashes of the before/after PM documents. SHA-256 operations are serialized to prevent race conditions. At stop, the final actual editor document must equal the reconstructed document. A receipt binds the initial snapshot, event count, chain head and final document digest. Validation replays and checks the whole local segment. These are hashes of the PM JSON model, not hashes of DOCX or the F1 canonical export model.

## Failure handling and resource limits

A missing transaction, invalid step, failed hash, invalid time or exceeded budget stops capture with an explicit error. There is no silent trimming or restart. Normal editing/document journalling remains separate. UI observers cannot throw into capture. Queued after-snapshots count toward the budget, not only retained step JSON. Default limits: 5,000 transactions, 8 MiB serialized accounting including pending snapshots, 1 MiB per document snapshot. These are bounded prototype limits, not a benchmark or an exact JavaScript heap-memory guarantee.

## Privacy and guarantees

This first adapter is MEMORY ONLY. Reload/close loses the process record; the document's existing IndexedDB journal has a different lifecycle. The UI warns before activation and offers a JSON export after verification. Exports contain the original snapshot, entered/pasted text, and reconstructible deleted text; they must not be treated as a harmless public activity summary.

The local preview is not sent to a mentor. It is not remote authorization, an immutable server log, an external timestamp, a signed authorship certificate or proof of identity. A user controlling the device can rewrite events and recompute an entirely consistent chain. No probability of human/AI authorship is generated. A sealed capture only covers the explicitly started/ended interval; later edits do not retroactively join it.

The rich transaction format intentionally does not force native ProseMirror history/formatting through the earlier limited plain-text ForensicPayload replay. Bridging verified captured PM segments to academic-object scoping, durable ledger storage, import verification UI, mentor sharing, crash recovery and server anchoring are later steps. This PR does not claim those are done.
